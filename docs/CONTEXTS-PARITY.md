# Contexts parity and platform boundaries

Research checked against [Contexts' official feature page](https://contexts.co/) on September 27, 2026. Contexts advertises fuzzy and learned search, sided-modifier Fast Search, individual-window cycling and current-app cycling, independently configured switchers, Space and inactive-window filtering, selected-window actions, a Space-grouped sidebar with badges, physical-trackpad gestures, dark appearance, and simultaneous presentation on every display.

This is the acceptance checklist for WindowHop, rather than a claim that every platform edge case has been validated. Native multi-display, multiple-Space, unsaved-document, and physical-device behavior needs the integration checks in [VALIDATION.md](VALIDATION.md).

## Discovery and filtering

`WindowItem` carries process identity, optional visible-Space membership, full-screen state, display identity, Space IDs/group title, optional badge text, and whether an entry represents a running application without usable windows. Missing metadata is explicit: unknown Space/display identity is not treated as an offscreen window.

`WindowListPolicy` filters the warm snapshot without Accessibility calls. It supports all Spaces, visible plus full-screen Spaces, and visible Spaces; independent normal/bottom/exclude settings for hidden and minimized windows; current-process-only filtering; optional display filtering; and inclusion of applications without windows. Moving inactive entries to the bottom is a stable partition, preserving MRU order within each portion. Exclusion takes precedence over bottom placement.

Public [CGWindowListCopyWindowInfo](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo(_:_:)) supplies bounds and on-screen state; [optionOnScreenOnly](https://developer.apple.com/documentation/coregraphics/cgwindowlistoption/optiononscreenonly) describes the on-screen list. WindowHop compares Quartz window bounds with Quartz display bounds, avoiding AppKit's opposite vertical coordinate convention. No window screenshot or title is read through Core Graphics. AppKit/AX remains the title source.

An offscreen hidden or minimized window is not necessarily on another Space. Exact classification uses the isolated, dynamically resolved read-only `SLSCopyManagedDisplaySpaces` and `SLSCopySpacesForWindows` interfaces. Their signatures and dictionary shape are independently described in [yabai's interface declarations](https://github.com/asmvik/yabai/blob/master/src/misc/extern.h) and [display implementation](https://github.com/asmvik/yabai/blob/master/src/display.c). No third-party implementation was copied. These are private APIs: their symbols and metadata can change with macOS updates. The public fallback keeps unknown entries visible instead of silently losing them. The optional `AXFullScreen` attribute is also undocumented; Space type is an independent full-screen signal.

Space labels are derived from the current desktop ordering, not user-defined names. The implementation does not move windows between Spaces, inject into Dock, or change SIP. Public AX discovery can still omit windows that an application does not expose; Space metadata cannot manufacture valid AX handles for those windows. A windowless application entry is explicitly labeled and activates the application only.

## Actions and application identity

Close reads the public [kAXCloseButtonAttribute](https://developer.apple.com/documentation/applicationservices/kaxclosebuttonattribute) and performs `AXPress`; minimize sets `AXMinimized`. Both run on the independent focus worker with bounded AX timeout and cancellation checks. Neither sends keystrokes to the current application. Windowless entries reject close/minimize.

Hide uses `NSRunningApplication.hide()`. Quit uses [NSRunningApplication.terminate()](https://developer.apple.com/documentation/appkit/nsrunningapplication/terminate()). Success means that macOS accepted the request, not that the application has exited: save dialogs can keep the app or window open. Index observations decide when entries disappear. There is no force-quit fallback and no retry of a potentially destructive action. A retained application identity, in addition to PID, prevents a stale entry from targeting an unrelated process after PID reuse.

## Dock badges

The public [NSDockTile API](https://developer.apple.com/documentation/appkit/nsdocktile) exposes an application's own tile; it is not a public registry for other apps' badge counts. Dock can expose `AXStatusLabel`, as described by the [Hammerspoon maintainer](https://github.com/Hammerspoon/hammerspoon/discussions/3251). WindowHop reads that exact optional value through a bounded background AX traversal and matches Dock's `AXURL` to the running app's bundle URL. It never extracts numbers from localized descriptions or equates an absent badge with a zero unread count. This is best effort: the attribute is undocumented, and an app absent from Dock or a changed Dock AX tree may have no badge.

## Physical trackpad gestures

Contexts' gesture starts at a physical edge of the trackpad, independently of the pointer's screen position. Public scrolling deltas and phases cannot identify that starting contact location. Apple's [gesture and touch guide](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/HandlingTouchEvents/HandlingTouchEvents.html) limits reliable `NSTouch` contact queries to touch responder handling. A [global NSEvent monitor](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html) observes delivery to other apps but cannot suppress it.

WindowHop's optional physical gesture integration uses an isolated dynamically loaded MultitouchSupport adapter and a scroll-event tap scoped to positively identified physical contacts. Its callback signatures are checked against [Subsurface's symbol declarations](https://github.com/mrkai77/Subsurface/blob/main/Sources/Subsurface/MTSymbolLoader.swift); the 96-byte contact record and normalized coordinates are described in [MTContact](https://github.com/mrkai77/Subsurface/blob/main/Sources/Subsurface/Touch/MTContact.swift), and contact phases in [MTContactState](https://github.com/mrkai77/Subsurface/blob/main/Sources/Subsurface/Touch/MTContactState.swift). Device-family matching follows the hardware identifiers documented by [SubsurfaceDevice](https://github.com/mrkai77/Subsurface/blob/main/Sources/Subsurface/SubsurfaceDevice.swift), admitting known MacBook/Magic Trackpad families and excluding Magic Mouse, Touch Bar, and unknown hardware. No third-party implementation is vendored.

Two fingers must originate in the same outer top corner; downward movement opens the list, vertical movement selects, and lifting both fingers commits. Only one trackpad can own a session. Ordinary scrolling that has already passed through cannot be acquired later, and captured momentum is suppressed after lift. Escape cancels with paired key-up suppression. The feature stays opt-in and stops on unsupported contacts or unavailable APIs. Trackpad attachment or a startup failure currently requires toggling the gesture off/on. Pure recognizer and synthetic event tests do not establish physical-device compatibility or actual callback ordering; those require manual validation. A pointer near a screen edge never substitutes for a physical trackpad origin.

## Performance boundaries

Core Graphics, SkyLight and Dock reads happen during background discovery, never during key handling. Discovery and focused-window actions use independent queues so unrelated AX stalls cannot hold a committed switch behind a scan. Dock traversal is time- and node-bounded. Filtering is linear over cached entries and preserves existing order; the default policy does not sort or perform IPC. Re-check whole-app input latency after enabling a large sidebar or multiple displays; search-engine microbenchmarks alone do not measure paint, event delivery, or AX activation.
